# Context

Startup idea prior-art engine: a founder types an idea; the system retrieves
the most relevant YC companies, shows a per-facet alignment grid, and computes
unoccupied whitespace in that neighborhood. Built as a retrieval and
evaluation study with a UI, not a scored "validator" — see `docs/adr/` for why.

## Glossary

**relevance**
The internal retrieval score used to rank candidates against a query. Never
displayed to the user — it's an implementation detail of ranking, not a
claim about the world.

**alignment**
The displayed per-facet same/different grid between the founder's idea and
one retrieved company. This is what "similarity" means when a user sees it
on screen.

**idea facet**
A property that both an idea and a company possess, making same/different
comparison meaningful. Bilateral. Five facets: `customer`, `problem`,
`mechanism`, `wedge`, `business_model`. Each is a controlled enum (for
deterministic comparison) plus a free-text span (for display).

**cohort signal**
A property only companies possess — never the founder's idea — aggregated
across the retrieved neighborhood. Unilateral: `stage`, `status`, `batch`,
`team_size`. Not a grid column, because a typed idea has no stage; comparing
it to a company's stage would be a category error. Displayed as neighborhood
statistics (e.g. "9 companies, 6 inactive, median batch W19"), never as an
interpretive verdict.

**whitespace**
An idea-facet enum value that is unoccupied across the retrieved cohort —
computed by counting occupants per value, never generated by the model.
Claude writes prose around a whitespace finding; it does not decide what
counts as whitespace.
